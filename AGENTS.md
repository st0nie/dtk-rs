# dtk-rs — agent guide

Rust bindings for DTK6 (dtkwidget): write deepin apps with DTK UIs in pure Rust.

## Layout

```
dtk-sys/     FFI layer, unsafe. links = "dtk6widget"
  cpp/       C++ shim: shim.cpp (hand), dtk_{gen,core,gui}_shim.cpp (generated), relay.cpp
  include/   headers, relay.h has Q_OBJECT (needs moc)
  src/lib.rs      cxx::bridge #1, hand-written core
  src/{gen,core,gui}_ffi.rs  cxx::bridges #2-4, GENERATED by tools/gen.py
  build.rs        pkg-config Qt6/DTK6, runs moc, c++17 + -fPIC
dtk/         safe wrappers
  src/lib.rs      hand-written core classes
  src/widgets.rs  GENERATED by tools/gen.py (146 DTK Widget classes)
  src/core.rs, src/gui.rs GENERATED audited pilots (3 DCore, 3 DGui)
tools/gen.py scans DWidget headers plus selected DCore/DGui pilot headers
GEN_REPORT.md / GEN_CORE_REPORT.md / GEN_GUI_REPORT.md coverage reports (pilot != full library)
TODO.md      known gaps
ARCHITECTURE.md how the binding works: layers, type mapping, signal/lifetime design
```

**Generated files** (regenerate, don't hand-edit): `dtk/src/{widgets,core,gui}.rs`, `dtk-sys/src/{gen,core,gui}_ffi.rs`, `dtk-sys/cpp/dtk_{gen,core,gui}_shim.cpp`, `dtk-sys/include/dtk_{gen,core,gui}_shim.h`, and all `GEN*REPORT.md`.

## Commands

```sh
cargo build                                    # build all
cargo run --example demo                       # GUI demo
QT_QPA_PLATFORM=offscreen ./target/debug/examples/demo --smoke   # headless smoke test
python3 tools/gen.py && cargo build            # regenerate bindings
```

Run `python3 -m unittest tools.test_gen`, `cargo test --workspace --all-targets`, and offscreen examples `demo --smoke`, `mpsc_eventfd --smoke`, `paint_widget --smoke`, `dialog_selfcheck`, `lifetime_selfcheck`, `threading_selfcheck`, `opaque_lifetime_selfcheck`, `layout_selfcheck`, `variant_selfcheck`, `action_selfcheck`, `model_selfcheck`, `no_application_selfcheck`, `owned_selfcheck`, `ownership_transfer_selfcheck`, `image_selfcheck`, `value_types_selfcheck`, `table_header_selfcheck`, `signal_reentrancy_selfcheck`, `core_paths_selfcheck`, `gui_helper_selfcheck`, `gui_image_selfcheck`, `gui_font_selfcheck`, `config_selfcheck`, plus `cargo run -p dtk-sys --example guard_selfcheck` offscreen. Keep generator output reproducible.

## Hard rules

- Requires Linux with Qt6 + DTK6 dev packages (pkg-config must find `Qt6Widgets`, `dtk6widget`, etc.). Not cross-platform.
- Rust edition 2024. `unsafe` blocks need `unsafe extern` etc. — edition 2024 lint strictness applies. Create `DApplication` before any GUI QObject/QWidget; constructors check this **and the QApplication GUI thread** before Qt allocation. Never touch the global relay map from worker threads; worker `unregister_callback` is a no-op for GUI-owned ids.
- QObject/widget constructors return `Owned<T>`; their dereferenced `Clone` views share a Qt `QPointer` liveness guard, are `!Send`, GUI-thread-only. Native Qt parent deletion invalidates them. `Owned<T>` queues deferred deletion on drop only if Qt never adopted the object: the guard records `ParentChange`, so an original owner cannot delete after Qt reparents and later transfers the object. `deleteLater` needs an active event loop. Do not infer ownership from a `take*` name: local `DListView::takeHeaderWidget` returns a borrowed, still-parented widget that native code deletes next event turn; `QMainWindow::takeCentralWidget` transfers ownership. Opaque borrowed returns, reentrant destruction, post-loop cleanup and `DApplication` RAII remain incomplete. Dropping the Rust app handle does NOT destroy native QApplication; never add `delete app` in Drop without proving it cannot run inside a native signal/event frame. Do not claim the entire public API memory-safe (see TODO.md).
- Value-type wrappers (QColor, QFont, QVariant, QImage, QBrush, QPainterPath, QKeySequence, QUrl, DPalette, ...) free via shim `*_delete` in `Drop`. `WaterMarkData` returned by value or const& is copied into an owned opaque allocation; never let a C++ reference escape. Generated non-QObject `new()` returns `OwnedOpaque<T>` with a generated C++ deleter; unguarded pointer getters are `unsafe` and have native API-specific ownership (not assumed borrowed or transferred). Do not add `Clone`/`Copy` to opaque pointer views.
- Four cxx bridges (hand + Widget + DCore + DGui pilots); generated QObject/QWidget base pointers are adjusted by C++ `static_cast` before `as _` casts across bridges (sound per audit in tools/gen.py). Never guess QWidget ancestry by name.
- DCore `DConfig::create`/`createGeneric` are individually audited transfers: the hand-bound `create_for_app`/`create_generic` return `Option<Owned<DConfig>>`. DConfig::globalThread is a borrowed QThread; never delete it. Native DConfig::setAppId must run before QCoreApplication; generated `set_app_id` is unsafe and does not require an existing app. Current safe constructors require GUI DApplication until a separate QCoreApplication lifetime model exists.
- New DTK method → usually regenerate with gen.py, not handwritten. If param types are unmapped (other QList types, QPrinter*, ...), they land in domain GEN*REPORT.md skipped. QHash<QString,QString> returns convert to owned BTreeMap<String,String> via alternating UTF-8 key/value strings; no string delimiters or borrowed Qt storage (see TODO.md).
- Signals: use `connect_signal*` / typed helpers; Qt object destruction releases callbacks automatically; `dtk::unregister_callback(id)` disconnects early. Nested emission of the same signal queues copied arguments until the outer FnMut returns; cancellation discards queued invocations (never alias &mut).
- `.codegraph/`, `target/`, `tools/__pycache__/` are gitignored scratch — don't commit.

## Style

- Minimal diffs. Hand-written code lives in `dtk/src/lib.rs` / `dtk-sys/src/lib.rs` + `cpp/shim.cpp`; keep generator-owned files generator-owned.
- Widget type mapping conventions (QString↔&str, enums→i32 with `dtk::qt` constants) are documented in README.md "Design". New DCore/DGui pilot enum inputs use Rust types with C++ value getters generated from native headers; untyped enum inputs remain `unsafe`. Do not guess C++ enum discriminants in Rust.
