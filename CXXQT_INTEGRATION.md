# CXX-Qt integration decision

Status: **adopted for imported Qt/DTK QObject signals and const methods**;
the signal layer is generated (phase 2/3, section 8). Scope: dtk-rs on Linux, Qt 6.8.0, DTK 6.7.47, CXX-Qt 0.10.0.
Related: [ARCHITECTURE.md](ARCHITECTURE.md),
[RUNTIME_SAFETY_AUDIT.md](RUNTIME_SAFETY_AUDIT.md),
[OWNERSHIP_HAND_REPORT.md](OWNERSHIP_HAND_REPORT.md) (CXX-Qt section).

## 1. Decision

1. Add a workspace crate, **`dtk-cxxqt` (edition 2024)**, containing one
   `#[cxx_qt::bridge]` with `unsafe extern "C++Qt"` imports of existing DTK
   classes. It never constructs, owns, deletes or mutably borrows a QObject.
2. CXX-Qt provides typed signal connection code (`QObject::connect` against the
   real member-function pointer, `QMetaObjectConnectionGuard`) and `QString`
   interop from `cxx-qt-lib` (QtCore only, `default-features = false`).
3. dtk-rs keeps ownership, liveness and borrowing: `dtk` calls the import only
   with a guarded live pointer inside a `dtk_sys::NativeCall`, and the CXX-Qt
   functor only queues owned values into the existing dtk-sys callback runtime.
4. Every imported receiver is `self: &T`. **`Pin<&mut T>` and `&mut T` are
   banned** and the hand audit fails closed if one appears.
5. Mutating C++ methods remain raw-pointer dtk-sys shims (generated by
   `tools/gen.py` or hand-written), executed under `NativeCall`.
6. Worker→GUI delivery stays on `dtk::threading::GuiSender`; CXX-Qt's
   `CxxQtThread` cannot target imported QObjects (KDAB/cxx-qt#1155).
7. No edition-2021 isolation crate: the edition-2024 failure recorded on Rust
   1.97 was not reproducible (section 2).

## 3. Runtime probe: `dtk/examples/cxxqt_signal_selfcheck.rs`

Runs offscreen in both profiles through `tools/check.sh`. Each row is an
assertion in the example, not a manual observation.

| Requirement | Assertion |
|---|---|
| Typed connect with real DTK class | `DSwitchButton::on_checked_changed`, `DLineEdit::on_text_changed`, `DSlider::{on_value_changed,on_range_changed}`, `DTabBar::{on_current_changed,on_tab_moved}`, `DDialog::on_visible_changed`, `DSearchEdit::on_text_changed` (inherited signal via subclass import) all connect and deliver expected values |
| RAII disconnect | value delivered, `drop(connection)`, next `set_checked` delivers nothing |
| `release()` keeps connection; id interoperates | released id still delivers; `unregister_callback(id)` disconnects; `is_connected` false |
| Callback released on Qt destruction | `delete_later` through a **shared clone view**; after the loop `Weak` of a captured `Rc` is dead, `is_connected()` false, dropping the stale `Connection` and dead `Owned` is a no-op |
| Deferred delivery after the `NativeCall` | the callback calls `view.is_checked()`, which opens a fresh `NativeCall`; that panics (and the logged value would be missing) if the closure ran inside `set_checked`'s still-open transaction |
| Nested emission queued FIFO, `FnMut` never reentered | callback calls `set_checked(false)`; log is exactly `[true, false]` and length stays 1 inside the first invocation |
| Cancellation from inside the callback | dropping its own `Connection` discards the value queued by the nested emission (`calls == 1`) |
| Owned argument conversion | `QString` → `String` inside the emission: `"中文 ✓ dtk-rs"` and `""` |
| Foreign thread | worker `unregister_callback(id)` returns `false`, connection keeps working |
| Application scope | a released connection on a forgotten owner is disconnected by scope exit; `dtk_sys::callback_registry_is_empty()` after `with` returns (includes the new typed-connection table) |

Unit tests in `dtk-sys/src/native_signal.rs` cover token delivery, functor
destruction (guard retired, callback cancelled) and failed-connect rollback.

## 4. API shape for imported QObject methods/properties

### Borrowing rule

| Construct | Allowed | Reason |
|---|---|---|
| `fn m(self: &T, ...)` for C++ `const` methods | yes, inside `NativeCall` on a guarded live pointer | cxx opaque types contain `UnsafeCell` (`cxx::private::Opaque`), so `&T` asserts neither immutability nor exclusivity of the C++ object; reentrant Qt aliasing through other views is permitted |
| `fn m(self: Pin<&mut T>, ...)` | **no** (audit error) | asserts a unique borrow; shared `Clone` views and reentrant Qt callbacks would alias it; cannot be produced from `&self` soundly |
| `#[qsignal] pub(self) fn s(self: &T, ...)` | yes | generated `connect` takes `T const&`; no emitter generated |
| public `#[qsignal]` | no (audit error) | would expose a Rust emitter and needs a `const` C++ signal |
| `extern "RustQt"`, `#[qproperty]`, `#[qinvokable]`, `impl cxx_qt::Threading` | not in this crate (audit error) | Rust-defined QObjects need their own ownership/borrow design (section 6) |
| non-const C++ methods | via dtk-sys raw-pointer shims | CXX would declare a `const` member pointer for `&T`; `Pin<&mut T>` is banned |

`tools/audit_hand.py` enforces this table: it rejects `Pin<`, `&mut`,
`"RustQt"`, `Threading`, `#[qinvokable]`, `#[qproperty`, non-`&T` receivers,
non-`pub(self)` signals and imports without glue, and lists every audited item
in `OWNERSHIP_HAND_REPORT.md`. `tools/check.sh` verifies the report is current.

### Signals

```rust
let connection: dtk::Connection = line_edit.on_text_changed(|text: String| { ... });
let id: usize = switch.on_checked_changed(|on| { ... }).release();
dtk::unregister_callback(id);
```

1. `dtk` opens `NativeCall`, takes `live_ptr()` (panics on a dead view),
   casts to the dtk-cxxqt opaque type (both bridges name the same C++ class).
2. `dtk_sys::native_signal::connect` registers the closure as an ordinary
   callback id (`Cb::Owned`) and hands a `SignalToken<A>` to the connector.
3. CXX-Qt connects with `AutoConnection` and the **sender as context**, so Qt
   destroys the functor with the sender. The functor ignores CXX-Qt's `&T`
   sender argument, converts arguments to owned values and calls
   `token.emit(value)` → `runtime::emit_signal(id, SignalEvent::Owned)`.
4. The user closure runs from the same pump as relay callbacks: after all
   native transactions return, FIFO per id, panic-contained, cancellable.
5. `Connection` is `!Send`, `#[must_use]`; Drop/`disconnect()` →
   `unregister_cb(id)` → drop the `QMetaObjectConnectionGuard` on the owning
   thread. Functor destruction (sender death) cancels the id and **retires**
   the guard and capture to a Rust cleanup boundary, never dropping user state
   inside a QObject destructor.
6. Scope exit unregisters every scoped id before native teardown.

The closure is `FnMut + 'static` and need **not** be `Send` (CXX-Qt's `Send`
bound is satisfied by the token; emission or drop on a foreign thread is
ignored). It never receives a native reference.

Trade-off: delivery is deferred, like every non-synchronous dtk callback. Code
that must answer within the emission (vetoes, return values) uses event
overrides with synchronous borrows, not signals.

### Methods and properties

- Read-only: import C++ `const` getters with `&T` (e.g.
  `DSwitchButton::is_checked`, inherited `QAbstractButton::isChecked() const`)
  and wrap them like any guarded method (`NativeCall` + `live_ptr`).
- Write: keep generated/hand shims (`set_checked` uses
  `abstract_button_set_checked` with a native `qobject_cast`).
- Q_PROPERTY: getter (`&T`) + setter shim + NOTIFY as a typed signal; no
  `#[qproperty]` (RustQt-only).
- Value arguments: owned conversion inside the emission (`QString` → `String`
  today). cxx-qt-lib value types (`QColor`, `QPoint`, `QSize`, `QRect`, `QUrl`,
  `QVariant`, …) are the intended next signal argument types.
- Pointer arguments (e.g. `DButtonBox::buttonClicked(QAbstractButton*)`) are
  **not** imported yet: converting them requires creating a guarded view inside
  the emission and an explicit borrowed-pointer contract per signal.

### Interaction with existing systems

| System | Effect |
|---|---|
| Callback registry | one id space; `unregister_callback`, scope cleanup and `callback_registry_is_empty` cover typed connections |
| `NativeCall` | connect/getters run inside a transaction; signals never call back synchronously |
| Synchronous borrows (paint/guard callbacks) | emission only enqueues; dispatch waits until the borrow ends |
| Shared guarded handles | clones are independent; closures capture clones; no exclusive borrow is created |
| String relay (`connect_signal*`) | kept for signals not yet imported; typed `on_*` replaces the former string-based `DLineEdit::on_return_pressed`/`DSwitchButton::on_checked_changed` helpers |

## 5. CxxQtThread gap (KDAB/cxx-qt#1155)

Evidence: `CxxQtThread` is generated only for `extern "RustQt"` QObjects using
`CxxQtGuardedPointer`, which the object must know about. On an import,
`impl cxx_qt::Threading for DSwitchButton {}` fails with
`QObject with name 'DSwitchButton' not found!`. Issue
[#1155](https://github.com/KDAB/cxx-qt/issues/1155) ("Support Threading on all
(even imported) QObjects", open since 2025-01-13) proposes a separately managed
context QObject plus a GUI-thread `QPointer`, and notes `moveToThread` would
have to become `unsafe`.

Workaround strategy:

1. Keep `dtk::threading::GuiSender<T: Send>`: worker → mpsc + coalesced
   eventfd → `QSocketNotifier` on the GUI thread → handler that uses guarded
   views. No QObject pointer crosses threads; owner destruction yields
   `BrokenPipe`; batching prevents starvation. It already implements the
   #1155 shape (context = notifier, guarded GUI-side access).
2. Typed signal tokens are thread-checked: a foreign-thread emission or functor
   drop is ignored, so CXX-Qt's `Send` bound cannot move Qt access off-thread.
3. Do not expose `moveToThread`; imported objects stay on the application
   thread (`require_application` already checks the owner thread).
4. Re-evaluate when #1155 lands: adopt only if it supports imported types
   without exposing the object across threads and `moveToThread` safety is
   resolved; it could then replace the eventfd, not the guarded-view model.

## 6. Migration path for QtCore/QtGui coverage

| Phase | Content | Exit criteria |
|---|---|---|
| 1 (done) | `dtk-cxxqt` bridge, typed signals for DSwitchButton, DLineEdit, DSearchEdit, DSlider, DTabBar, DDialog; `Connection`; audit; selfcheck | `tools/check.sh` Debug + Release |
| 2 (done) | `tools/signals.py` (run by `tools/gen.py`) emits the bridge, connectors, cast header and `dtk/src/signals_gen.rs` from `Q_SIGNALS:` of every class reachable from a wrapper; per-signal audit rows; `GEN_SIGNAL_REPORT.md` | generated files in check.sh reproducibility manifest |
| 3 (done) | Value-type signal arguments; hand heap wrappers for trivially copyable values replaced by cxx-qt-lib by-value types (section 8) | per-type audit table in `OWNERSHIP_HAND_REPORT.md`; `signal_values_selfcheck` |
| 4 (partly done) | QtCore/QtGui/QtWidgets QObjects imported for typed signals (`QTimer`, `QAction`, `QAbstractItemModel`, `QWidget`, `QAbstractButton`, ...). Pointer-valued signals via guarded-view conversion remain | per-type borrowed-pointer contract |
| 5 | Rust-defined QObjects (`extern "RustQt"`) for models/delegates, owned by `Owned<T>` and dispatched under synchronous borrows | separate design: CXX-Qt invokables take `Pin<&mut T>` for Rust state, which must be reconciled with reentrant Qt callbacks before admission |

Throughout: no public API exposes CXX-Qt types except `QString` re-exported from
`dtk-cxxqt`; dtk-rs wrappers remain the stable surface.

## 7. Costs

Build (clean `CARGO_TARGET_DIR`, debug, `cargo build -p dtk`, this machine,
bash `time`):

| Tree | Wall | User CPU |
|---|---|---|
| HEAD before this change (no CXX-Qt) | 57.4 s | 62.4 s |
| With `dtk-cxxqt` (cxx-qt, cxx-qt-lib QtCore, bridge) | 132.0 s | 746.1 s |

The increase (+75 s wall, ~12× CPU) is dominated by cxx-qt-lib's C++ sources
and moc. It is a one-time clean-build cost; incremental Rust edits do not
rebuild it. Staged builds (`-p dtk-cxxqt` then `-p dtk`) rebuilt the CXX-Qt
C++ twice (feature unification differs per package selection), so CI should
build the workspace in one invocation, as `tools/check.sh` does.
cxx, cxx-build and cxx-gen must move in lockstep (section 2).
Runtime: one boxed `Any` per emission plus the existing queue; the functor is
a native lambda (no `DtkRelay` QObject per connection).

## 8. Generated signal layer and by-value Qt types

### Signals (`tools/signals.py`)

- Input: `Q_SIGNALS:` sections of every exported class in DWidget/DGui/DCore
  and QtCore/QtGui/QtWidgets that is an ancestor of a dtk-rs QObject wrapper
  (generated widgets/objects and hand-written wrappers). DTK `typedef QFoo DFoo`
  aliases (`dwidgetstype.h`) resolve to the Qt class. `#ifdef` feature regions
  that are not defined by the pkg-config build (e.g. `DTK_TITLE_DRAG_WINDOW`),
  DTK5-only and Qt-deprecated regions are excluded.
- Each declaring class is imported **once** with only its own signals. The
  connector receives the wrapper's live `QObject*` and casts it with
  `qobject_cast<const Declaring *>`; a null result returns no connection
  (`Connection::new` panics). This replaces per-subclass redeclaration and is
  correct for secondary bases (`DObject` mixins), unlike a Rust pointer cast.
- Every wrapper gets `on_*` for its class and all ancestors; a more-derived
  signal with the same name hides the base one. Overloaded signal names are
  skipped (the member pointer would be ambiguous).
- Argument conversion inside the emission (owned, never a reference to Qt
  storage): scalars and unscoped enums (`i32`) copied; `QString`,
  `QStringList`, `QByteArray` → `String`, `Vec<String>`, `Vec<u8>`; cxx-qt-lib
  trivial values cloned; `QList<int>`/`QVector<int>`/`QList<QUrl>` → `Vec`;
  `QVariant`, `QFont`, `QImage`, `QPixmap`, `QIcon`, `QBrush`, `QPalette`,
  `QPainterPath`, `QKeySequence`, `DPalette`, `DDciIcon` → a C++ copy held by
  `dtk_sys::native_signal::OwnedValue` (matching dtk-sys deleter; deleted if the
  event is cancelled) then adopted by the dtk wrapper; `QModelIndex` →
  `QPersistentModelIndex` copy (`dtk::PersistentModelIndex`), because a plain
  index is only valid until the model changes.
- Not generated (listed with reasons in `GEN_SIGNAL_REPORT.md`): pointer
  arguments (need per-signal guarded-view contracts), QFlags and scoped enums
  (no implicit int conversion), other containers, overloaded names,
  `QObject::destroyed` (emitted during destruction), QSocketNotifier
  `activated` (level-triggered hand relay).
- String-based relay helpers that duplicated generated signals were removed
  (`on_clicked`, `on_timeout`, `on_triggered`, `on_current_index_changed` now
  return `Connection` with the full typed argument list).

### `dtk::PersistentModelIndex`

Owned `QPersistentModelIndex`: Qt updates it across inserts/moves and
invalidates it in `~QAbstractItemModel` (`qabstractitemmodel.cpp`:
`invalidatePersistentIndexes`), so holding one never keeps or dangles the
model. Its destructor unregisters from the model's private table; Rust drops
it through `defer_cleanup` while a native frame is active. `data()` and the
new `QAbstractItemModel::index`/`set_index_data` run inside a `NativeCall`;
indexes of another model are rejected in C++ (`index.model() != model`).

### By-value Qt types (cxx-qt-lib, `qt_gui` feature)

`QColor`, `QPoint(F)`, `QSize(F)`, `QRect(F)`, `QMargins(F)` and `QUrl` are
re-exported from cxx-qt-lib and declared as `type T = cxx_qt_lib::T` in all
four dtk-sys bridges (`cxx::kind::Trivial`). cxx-qt-lib's C++ static-asserts
their size/alignment and trivial copyability against the installed Qt (QUrl:
`rust::IsRelocatable<QUrl>` with Clone/Drop calling the C++ copy constructor/
destructor). Returns are C++ copies, parameters `const T &`; there is no heap
allocation, deleter, scope guard or QObject reference, so they are
independent of the application scope. The previous `*_new/*_delete` shims
and `value_wrapper!`s for these types were removed. dtk-sys locates
cxx-qt-lib's exported headers through its `links` metadata
(`DEP_CXX_QT_LIB_CXX_QT_MANIFEST_PATH`). Non-trivial or mutable-reference
types (`QFont`, `QImage`, `QPixmap`, `QVariant`, `QPalette`, ...) keep the
audited heap wrappers (their `&mut` mutation APIs and DTK `DPalette` subclass
are not modelled by cxx-qt-lib). `rgba_u32` moved to `dtk::ColorExt`.
