dtk-rs resolves the Pin<&mut T> question for painting/models without CXX-Qt `extern "RustQt"`:
- gen.py maps `QPainter*` params → `&crate::Painter` (kind `painter`), `const QStyleOption(ViewItem) */&` → owned/borrowed `QStyleOption`/`QStyleOptionViewItem` (kind `styleopt`), `QModelIndex` → `crate::PersistentModelIndex` (kind `index`), `QStyle*` → guarded `QStyle` object view (QT_PTRS). Generated methods with painter/styleopt args use `dtk_sys::NativeCall::paint()` which is admitted inside the paint callback's SynchronousBorrow (C++ `runtime_paint_call_new`). `UNSAFE_PAINTING` in gen.py excludes DStyleHelper/DStylePainter/DStyledIconEngine::setFrontRole (raw retained pointers).
- `Painter::on_image(&mut QImage, |p| ..)` creates/ends a QPainter (painter_begin_image/painter_finish).
- Owned QStyleOption copies/initFrom clear `styleObject` (and widget/index for view-item clones) so stored options never dangle.
- `ListModel<T>` (dtk/src/lib.rs): C++ `RustListModel : QAbstractListModel` in shim.cpp stores only a callback id (`Cb::Model`, `dtk_sys::ModelCallbacks`); Qt rowCount/data/setData run Rust hooks under SynchronousBorrow (QObject access inside panics, contained, "no data"); Rust insert/remove/update/reset run inside one NativeCall with begin*/end* and never hold the RefCell borrow while Qt is notified.
- `PaintDelegate::new_styled` lends the initialized QStyleOptionViewItem. Regression: `dtk/examples/paint_model_selfcheck.rs`.
