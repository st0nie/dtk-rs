In dtk-rs, delaying QSocketNotifier callbacks without pausing its native level polling can enqueue duplicate activations before a handler drains the fd; a second handler then blocks reading already-consumed data. A source-level GDB stack confirmed this in the unchanged `demo --smoke` pipe read. `dtk-sys/cpp/relay.cpp` coalesces readiness per pending/running id for all relay signatures (including legacy `activated(int)`), disables native polling on first activation and counts outstanding deliveries in a scope-tracked notifier child. `ReadyBoundary` in `dtk-sys/src/runtime.rs` resumes only after callback completion; `set_enabled(false)` updates desired state and must remain disabled afterward. Keep this special readiness policy separate from ordinary signals, which retain copied FIFO emissions. `runtime_borrow_selfcheck` exercises undrained fd readiness during a modal loop, legacy typed fd callbacks and explicit disable. Ordinary Rust-only coalescing without native polling pause was insufficient.
