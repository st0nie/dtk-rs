dtk-rs uses `DApplication::with(name, |app| ...)`, `DApplication::with_quit_guard(name, guard, |app| ...)` and `QCoreApplication::with(name, |app| ...)`; `DApplication::new`/`new_with_quit_guard` were removed and no owning/Clone app token exists. One native `ApplicationRuntime` lives in `dtk-sys/cpp/application_runtime.cpp` / `include/application_runtime.h`; both scope owners stay private until outer user/native frames return (including ordinary panic unwinding), so native destruction happens only after the Rust closure and Qt exec frames return. The public application is a borrowed token that cannot enter 'static Qt callbacks or escape as the scope's return value; `exec` exit alone does not close a scope — exit the process only after `with` returns.

Scope teardown cleans up registered QObjects and timers even if `exec` never ran or during panic unwinding, without relying on an event loop or DeferredDelete. Shared per-scope closing guards invalidate all QObject views, including process-global DTK singletons (old views stay invalid even if a later app reuses the singleton); borrowed opaque pointers watch app scope, while uniquely owned opaque constructors/copies stay independent. Shutdown blocks constructors/object access/callback dispatch, drops scope callbacks outside RefCell borrows, disconnects relays, synchronously deletes GUI top-level windows and verified constructor/transfer/helper QPointer entries, then app children/application — no extra event turn, no global DeferredDelete drain, native parents preserved. `Owned::new` registers QPointers only for constructors and audited ownership transfers; never delete borrowed DTK singleton getters (DWaterMarkHelper post-routine queues deleteLater; DMessageManager function-local static; DPaletteHelper borrowed global; DGuiApplicationHelper cleaned via qAddPostRoutine(staticCleanApplication) — DFontManager/DMessageManager/DPaletteHelper/DWaterMarkHelper survive destruction at stable addresses, QPointer evidence is not enough).

Qt Quit honors close vetoes (QApplication::event(Quit) -> closeAllWindows -> ... -> DtkMainWindowEx::closeEvent): a Rust close callback permanently returning false prevents quitting; test quit with close permitted, then restore a false close guard just before scope return so cleanup is non-vetoable and done by direct deletion at the outer boundary. Qt exec() is static: a unified owner storing QCoreApplication* must call QApplication::exec() for GUI and QCoreApplication::exec() for headless scopes.

Native DTK worker threads must be joined during application teardown: the GUI milestone exposed an intermittent `value_types_selfcheck` SIGSEGV after functional checks succeeded (ordinary runs reproduced at iteration 35; a low-overhead signal trace caught iteration 65). The crashing worker stack was `QThread::exec -> QEventLoop::exec -> sendPostedEvents -> QCoreApplication::notifyInternal2 +0x8c`. Installed Qt6.8 disassembly shows the fault is the second load/dereference of `QCoreApplication::self` after main-thread application destruction cleared it. Qt source `src/corelib/kernel/qcoreapplication.cpp:1137–1165` and the notify() warning explicitly require non-Qt library event threads to stop before an overridden application begins destruction. DTK6 `DConfig::globalThread()` is a native-owned Q_GLOBAL_STATIC `DConfigThread : QThread` (dtkcore/src/dconfig.cpp), NOT Qt's QDaemonThread; Qt's DBus daemon is exempt. dtk-rs ApplicationRuntime must retain only a borrowed QPointer to this native DTK worker, quit() and wait() while the app still lives and before native object/app deletion, then restart it only after a subsequent Core/GUI app is fully constructed. Never delete the borrowed QThread, use terminate/sleeps/global DeferredDelete drains, or guess the crash is a widget destructor without checking the native thread stack.

Stopping the worker: do not directly call QThread::quit when closing ApplicationRuntime — Qt exits its event loop without completing accepted normal-priority MetaCalls (e.g. DGuiApplicationHelper's async configuration updates), leaving them until another application scope restarts the borrowed native thread. Instead queue a private QObject context on DConfigThread, enqueue the FIFO stop MetaCall behind accepted work, have the marker call quit on the worker thread and move its helper back to the main thread, then wait/join before deleting helper/app. If the worker already appears stopped (`isRunning()==false`), still call `QThread::wait()`: isRunning alone does not prove native thread-local destructor cleanup has completed. Never queue the marker on QThread's QObject itself (main-thread affinity), globally flush arbitrary Qt events, or delete the borrowed native thread. Keep scope closing and callback dispatch disabled for the whole stop/join protocol; restart the worker only after the next Core/GUI app's native construction is complete. Native regression `runtime_worker_probe.cpp` latches current event A, queues an actual DConfig setValue/readback B using an owned in-memory test backend, and releases A from a producer only after stop-marker acceptance; assert B completes before with returns, including no-exec/panic and GUI/Core transitions — actual worker task roundtrips test restart, not just isRunning.

Full validation: `bash tools/check.sh` — generator tests + 15 output hashes, fmt, Debug/Release workspace all-targets check/clippy (-D warnings)/build/test, separate doctests (all-targets excludes them), then every example with GUI offscreen and Core display variables unset. Targeted: `gui_application_selfcheck`, `core_application_selfcheck`, sys `guard_selfcheck` (native deletion, repeat scopes, callbacks, panic/reentry, scope-escape compile-fail, fresh argv, recursive exec). GUI scoped guards need shared per-scope closing state, not only QPointer liveness (Qt 6.8 / DTK6 6.7.47, native offscreen probe 5x DApplication+DMainWindow; matched sources dtkwidget 6.7.47.1-1 / dtkgui 6.7.47). General native reentrant method safety and unsafe opaque allocation lifetimes within a live scope are not claimed solved; do not claim the entire public API memory-safe — see `TODO.md`.
