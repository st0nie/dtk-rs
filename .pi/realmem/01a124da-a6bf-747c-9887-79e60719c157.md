dtk-rs uses `QCoreApplication::with(name, |app| ...)` for scoped headless application lifetime. The native `CoreRuntime` UniquePtr exists only inside `with`; the public application is a non-Clone borrowed token that cannot enter 'static Qt callbacks or escape as the scope's return value. Native application destruction therefore occurs only after the outer Rust closure and Qt exec frames return, including ordinary Rust panic unwinding.
Scope teardown must clean up registered QObjects and application timers even if `exec` never ran (no-exec) and during panic unwinding; it must not rely on an event loop processing deferred deletions. Before deleting objects or timers, shutdown must reject new object creation and guarded-object access to prevent reentrancy. `Owned::new` registers QPointers only for constructors and audited ownership transfers, never arbitrary borrowed getters; cleanup must preserve native QObject parents. Guarded QObject views may escape but become invalid after the scope ends.
Dropping the Rust `DApplication` handle does not destroy native QApplication. Do not add `delete app` in Drop without proving it cannot run inside a native signal/event frame; reentrant destruction can invalidate native frames. Opaque borrowed returns, reentrant destruction, post-loop cleanup and GUI `DApplication` RAII remain unresolved. Do not claim the entire public API is memory-safe; see `TODO.md`. The scoped headless mechanism does not solve GUI `DApplication` shutdown.
