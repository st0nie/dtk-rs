In dtk-rs, QObject/widget constructors return `Owned<T>`; the dereferenced `T` views are non-owning, `Clone`, `!Send`, GUI-thread-only, and clones share a Qt `QPointer` liveness guard (native Qt parent deletion invalidates them; never dereference a dead QObject). `Owned<T>` queues deferred deletion on drop only if Qt never adopted the QObject: its guard records `ParentChange`, so the original constructor owner cannot delete an object after Qt reparents it and later transfers it to another owner — checking only the current parent is insufficient. Never infer native return ownership from a `take*` method name in the generator; e.g. `QMainWindow::takeCentralWidget` is an audited ownership transfer: an original constructor `Owned<T>` must not delete the object after Qt has adopted it and subsequently transferred ownership; preserve the guard's adoption history. `deleteLater` requires an active event loop; dropping handles after the GUI event loop ends does not give deterministic shutdown cleanup. Generated non-QObject `new()` returns `OwnedOpaque<T>` backed by a generated C++ deleter; do not add `Clone`/`Copy` to opaque pointer views. `OwnedOpaque<T>` must not implement `DerefMut<Target = T>` when `T` is a non-owning raw-pointer view — non-Clone/non-Copy alone is insufficient: `mem::replace(&mut *owner, borrowed_singleton_view)` can detach the original view beyond allocation deletion and cause the owner to delete borrowed/static storage. Native output APIs should accept `&mut OwnedOpaque<T>` and access its private stable allocation internally, not expose `&mut T`; QObject `Owned<T>` likewise does not expose `DerefMut` or an exclusive native `Pin<&mut T>` through Clone handles. Unguarded pointer getters are `unsafe` with native API-specific ownership/lifetime contracts — never assume a returned pointer is borrowed or transferred without auditing its native API. Separately, value-type wrappers (`QColor`, `QFont`, `QVariant`, `QImage`, `QBrush`, `QPainterPath`, `QKeySequence`, `QUrl`, `DPalette`, ...) own their allocations and free them through shim `*_delete` in `Drop`; their lifetime is distinct from guarded, non-owning QObject/widget views.
