Matching `apt source dtkwidget=6.7.47.1-1` and installed headers show `DSearchEdit : public DLineEdit`, while `DLineEdit : public QWidget, public DObject` owns a separate `QLineEdit` returned by `lineEdit()`. A `static_cast<QLineEdit *>(QWidget*)` of DSearchEdit is invalid even if its QPointer is live. The hand text getter in `dtk-sys/cpp/shim.cpp` must use a checked native DLineEdit/QLineEdit cast and the container's `text()`; Rust should pass the generated cached adjusted `widget_ptr()`, not cast its opaque DTK pointer to an assumed Qt base.
