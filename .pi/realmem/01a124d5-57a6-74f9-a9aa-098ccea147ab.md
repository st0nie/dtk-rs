In dtk-rs DCore bindings, `DConfig::create`/`createGeneric` are individually audited ownership transfers. The hand-bound `create_for_app`/`create_generic` return `Option<Owned<DConfig>>`. These factories run on a scoped QCoreApplication or GUI DApplication's owning thread. `DConfig::globalThread` is a borrowed QThread and must never be deleted by the caller. GUI wrappers still reject headless runtimes. Native `DConfig::setAppId` must run before QCoreApplication is constructed; the generated `set_app_id` is `unsafe` and does not require an existing application — do not impose the ordinary post-application constructor check on this pre-application initialization API.
