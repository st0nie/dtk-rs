dtk-rs has an edition-2024 workspace crate `dtk-cxxqt/` (`src/bridge.rs` = `#[cxx_qt::bridge]` with `unsafe extern "C++Qt"` imports of DSwitchButton, DLineEdit, DSearchEdit, DSlider, DTabBar, DDialog; `src/lib.rs` = unsafe connector fns taking `*const ffi::T` + `dtk_sys::native_signal::SignalToken<A>`). Safe API lives in `dtk/src/signals.rs` (`on_*` methods returning `dtk::Connection`, RAII; `release()` returns callback id). Runtime: `dtk-sys/src/native_signal.rs` registers `Cb::Owned` callbacks, the token queues `SignalEvent::Owned(Box<dyn Any>)` via `runtime::emit_signal`; functor drop cancels the id and retires the `QMetaObjectConnectionGuard` via `runtime::retire_value`. Rules enforced by `tools/audit_hand.py` (section in OWNERSHIP_HAND_REPORT.md): receivers must be `self: &T`, signals `pub(self)`, no `Pin<`/`&mut`/RustQt/Threading/qproperty/qinvokable, every import needs glue. Non-const methods stay dtk-sys raw-pointer shims (e.g. `abstract_button_set_checked`). `cxx`, `cxx-build` (dtk-sys) and `cxx-gen` (dtk-cxxqt build-dep) must be pinned to the same release (currently =1.0.205 / =0.7.205): CXX embeds the release in C++ symbol names, mismatch gives `undefined symbol ...cxxbridge1$198$...`. Clean debug `cargo build -p dtk` went from 57 s to 132 s wall (cxx-qt-lib C++). Decision doc: `CXXQT_INTEGRATION.md`; regression: `dtk/examples/cxxqt_signal_selfcheck.rs`.
