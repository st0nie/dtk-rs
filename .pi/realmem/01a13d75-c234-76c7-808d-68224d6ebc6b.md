dtk-rs has an edition-2024 workspace crate `dtk-cxxqt/` (`src/bridge.rs` = `#[cxx_qt::bridge]` with `unsafe extern "C++Qt"` imports of DSwitchButton, DLineEdit, DSearchEdit, DSlider, DTabBar, DDialog; `src/lib.rs` = unsafe connector fns taking `*const ffi::T` + `dtk_sys::native_signal::SignalToken<A>`). Safe API lives in `dtk/src/signals.rs` (`on_*` methods returning `dtk::Connection`, RAII; `release()` returns callback id). Runtime: `dtk-sys/src/native_signal.rs` registers `Cb::Owned` callbacks, the token queues `SignalEvent::Owned(Box<dyn Any>)` via `runtime::emit_signal`; functor drop cancels the id and retires the `QMetaObjectConnectionGuard` via `runtime::retire_value`. Rules enforced by `tools/audit_hand.py` (section in OWNERSHIP_HAND_REPORT.md): receivers must be `self: &T`, signals `pub(self)`, no `Pin<`/`&mut`/RustQt/Threading/qproperty/qinvokable, every import needs glue. Non-const methods stay dtk-sys raw-pointer shims (e.g. `abstract_button_set_checked`). `cxx`, `cxx-build` (dtk-sys) and `cxx-gen` (dtk-cxxqt build-dep) must be pinned to the same release (currently =1.0.205 / =0.7.205): CXX embeds the release in C++ symbol names, mismatch gives `undefined symbol ...cxxbridge1$198$...`. Clean debug `cargo build -p dtk` went from 57 s to 132 s wall (cxx-qt-lib C++). Decision doc: `CXXQT_INTEGRATION.md`; regression: `dtk/examples/cxxqt_signal_selfcheck.rs`.

dtk-rs typed signals are generated by `tools/signals.py`, invoked at the end of `tools/gen.py`. It scans `Q_SIGNALS:` of every exported DWidget/DGui/DCore and QtCore/QtGui/QtWidgets class that is an ancestor of a dtk-rs QObject wrapper (generated widget/object classes + `HAND_WRAPPERS` table), resolves `typedef QFoo DFoo` aliases from `dwidgetstype.h`, skips DTK5-only/qdoc/deprecated and undefined `#ifdef` feature regions (e.g. `DTK_TITLE_DRAG_WINDOW` would otherwise emit nonexistent `DTitlebar::mousePosMoving`). Outputs (generator-owned): `dtk-cxxqt/src/{bridge,connectors}.rs`, `dtk-cxxqt/include/dtk_cxxqt_casts.h` (qobject_cast helpers + value clone helpers), `dtk/src/signals_gen.rs`, `GEN_SIGNAL_REPORT.md`; all are in tools/check.sh's reproducibility manifest. Each declaring class is imported once; connectors take the wrapper's QObject* and qobject_cast to the declaring class (correct for DObject secondary bases). Heap value args are copied into `dtk_sys::native_signal::OwnedValue<T>` (deleter dropped if undelivered) then adopted by the dtk wrapper; QModelIndex args become `dtk::PersistentModelIndex`. Pitfalls: cxx-qt bridge rejects `#[allow]` attributes inside the bridge module (put `#[allow(clippy::missing_safety_doc)]` on `mod bridge;` in lib.rs); do not declare `type QObject = cxx_qt::QObject` in a cxx_qt::bridge (duplicate definition) — the bridge already has QObject; dtk-cxxqt build needs `../dtk-sys/compat` include for DThemeManager alias header. tools/audit_hand.py checks every import has `ffi::as_<Class>(` and `sender.on_<signal>(` glue in connectors.rs.
QColor/QPoint(F)/QSize(F)/QRect(F)/QMargins(F)/QUrl are cxx-qt-lib (`qt_gui` feature) by-value `Trivial` types re-exported from `dtk` and declared `#[namespace = ""] type T = cxx_qt_lib::T;` in all dtk-sys bridges (gen.py `CXXQT_VALUE_TYPES`, kind `qval`); dtk-sys build.rs finds cxx-qt-lib headers via `DEP_CXX_QT_LIB_CXX_QT_MANIFEST_PATH` parent `/include`. `rgba_u32` is `dtk::ColorExt`; constructors are `QColor::from_rgb/from_rgba`, `QUrl::from(&str)`.
