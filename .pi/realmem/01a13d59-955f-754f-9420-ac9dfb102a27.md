Re-verified 2026 on this machine: `#[cxx_qt::bridge]` with `include!(<QtCore/QObject>)` (empty bridge) and an imported DTK `DSwitchButton`/`DLineEdit` C++Qt bridge compile in an **edition 2024** crate with cxx-qt 0.10.0 and 0.8.1, cxx 1.0.202 and 1.0.205, on both rustc 1.97.1 (installed via `rustup toolchain install 1.97.1 --profile minimal`) and 1.99.0. The earlier recorded edition-2024 macro failure on 1.97 could not be reproduced with the same pinned versions (scratch crates under `.pi/cxxqt-e2024*`, `.pi/cxxqt-probe-e2024`). No edition-2021 isolation crate is needed. Notes: `CxxQtBuilder::cc_builder` is an `unsafe fn` (call inside `unsafe {}`); qt-build-utils emits `cargo::rustc-link-arg=-fuse-ld=gold|lld|mold` automatically; cxx-qt-lib 0.10.0 with `default-features = false` (QtCore only) adds ~75 s wall / ~9 min CPU to a clean debug build.
