In CXX-Qt 0.10.0 `unsafe extern "C++Qt"` blocks, a `#[qsignal]` declared with `self: &T` generates `QObject::connect(&self, &T::signal, &self, lambda)` taking `T const&` (no `Pin<&mut T>` needed for connecting), and the closure receives `&T`. But a public `&self` signal also declares a const C++ emitter, which fails to compile for non-const Qt signals (`cannot convert 'void (DSwitchButton::*)(bool)' to '... const'`). Declare the signal `pub(self) fn sig(self: &T, ...)` (parser treats `pub(self)` as private) to suppress the emitter; DTK signals declared `const` (e.g. `DLineEdit::alertChanged(bool) const`) work publicly. `impl cxx_qt::Threading for DSwitchButton {}` on an imported type fails at build with `error[cxxqt]: QObject with name 'DSwitchButton' not found!` — CxxQtThread is RustQt-only (KDAB/cxx-qt#1155). Closures must be `FnMut(&T, args) + Send + 'static` and run synchronously inside the Qt emission. cxx opaque types contain `UnsafeCell`, so `&T` to a live C++ object does not assert immutability; `Pin<&mut T>` does assert exclusivity.
